做血液肿瘤 panel 基本都绕不开 FLT3-ITD。这个变异讨厌的地方在于长度跨度很大，短的十几个 bp，长的能拉到一两百 bp。如果测序 read 只有 120 bp，遇到一条 180 bp 的串联重复，指望在 BAM 的 CIGAR 里直接看到 `180I` 是不现实的。不过只要 read 横跨串联重复拼出来的新接头，就会留下一截软剪切（soft-clip）。把跨过同一个接头的这批 reads 攒起来，就有机会把整段重复还原出来。

经典的 [FLT3_ITD_ext](https://github.com/ht50/FLT3_ITD_ext) 就是按这条路子做的：局部比对、候选延伸、聚类、再重比对算支持度。只是原版用 Perl 写，跑之前要先给局部参考序列建一套 BWA 索引，运行时还要外部调用 `samtools` 和 `sumaclust`。平时往容器或工作流里塞的时候，光处理这套外部依赖就挺别扭。

于是我用 Rust 把这条主线重写了一遍，做了 [ITDCall](https://github.com/pzweuj/ITDCall)。现在局部比对和聚类全在程序内部完成，输入收敛成 BAM 和参考基因组 FASTA，输出一个标准 VCF。顺带把一直混在一起算的两件事拆开了：探针捕获和扩增子的定量各自独立，目标区间也不再绑死在 FLT3 上。

## 检测思路：从软剪切到拆分长度

流程默认针对 FLT3 exon 14–15，会自动识别 hg19 / hg38 以及 `chr13` / `13`。先把落在目标区里的 reads 抽出来，用 k-mer 找种子，再做一次带状 Smith–Waterman 局部比对：

- **短 ITD**：重新比对之后，直接从插入信号里就能抓出来。
- **长 ITD**：单个 read 包不住整段插入，就试着把 soft-clip 那一截也锚回参考序列上，看两段坐标的相对位置能不能拼成一个串联重复。

找到接头后，用参考序列把候选两端补齐，再把相似的候选聚成一簇。

临床样本里的 ITD 经常不是纯复制——在重复一段序列的同时，中间还会夹带几个额外插进去的碱基。ITDCall 聚类后会把插进去的这部分拆开看：比如复制了 36 bp、中间多出 3 bp，VCF 里就会分别记成 `DUPLEN=36`、`INSLEN=3`、`SVLEN=39`。最后再把片段重比对回野生型（WT）和候选突变序列上，统计各自的支持量。

至于转录本坐标和 HGVS 命名，ITDCall 干脆没往里放。VCF 只管把基因组正链左对齐后的 `POS/REF/ALT` 和支持证据交干净，注释留给下游的 VEP 或 TransVar 去做。

## 探针捕获和扩增子，账要分开算

两类文库的片段生成逻辑完全不一样，硬用同一套计数口径肯定出偏差。

**探针捕获（`-m hc`）** 的片段是随机打断的，遇到长 ITD 时，左右两个接头两侧能跨过去的片段数经常不一样，一对 reads 也可能只跨到其中一侧。ITDCall 的做法是把左右两侧的有效边界支持分别统计后再取均值，所以结果里看到 `VD` 出现 `2.5` 这种小数很正常。分母 `DP` 的边界计数里，则会把野生型、突变序列外侧以及其他克隆的相关覆盖一并算进来。

**扩增子（`-m amplicon`）** 的片段起止位置是引物锁死的。一对 reads 哪怕两端都跨过了接头，它们也还是同一个片段，只能记一次。这里 `VD` 就是支持当前 ITD 的片段数，`DP` 则加上覆盖对应边界的 WT 片段和其他 ITD 克隆的片段。另外扩增子数据里大量 reads 起止坐标重合本来就是常态，所以 `0x400` 标记默认保留不过滤。

还有一个容易算错的地方是 `AF` 和 `AR`：

- VCF 里的 `AF = VD / DP`
- `AR` 则是用 `VD` 除以实际的野生型支持深度

拿一个简单的扩增子例子来算：60 个 WT 片段配 40 个 Mut 片段，`AF` 是 `0.40`，`AR` 是 `40 / 60`，约等于 `0.667`。单克隆看起来似乎可以用 `AF / (1 - AF)` 去反推，但如果样本里还存在另一个 ITD 克隆，那个克隆会对 `DP` 有贡献却不能算成 WT，用公式直接反推 `AR` 就会偏掉。

## 跑一下

常见用法两条命令就能搞定，分别对应探针捕获和扩增子：

```bash
# 探针捕获
itdcall -b sample.bam -r hg38.fa -o sample.itd.vcf -m hc

# 扩增子
itdcall -b amplicon.bam -r hg19.fa -o amplicon.itd.vcf \
  -m amplicon --genome hg19
```

几个常用的补充参数：

- **读取方式**：BAM 带有 `.bai` 索引时，默认的 `targeted` 模式会直接跳转读取目标区；如果想把未比对（unmapped）的 reads 也捞进来扫一遍，可以加上 `--read-mode loose`，代价是要顺序扫整个 BAM。
- **自定义区间**：不想只跑默认的 FLT3 exon 14–15，可以用 `--region` 或 `--bed` 指定其他目标区域。如果手头另有一份局部目标 FASTA，还能额外传 `--target-fasta`，程序会在参考基因组里定位并识别正负链方向。最终输出的 VCF 会统一换算到参考基因组正链并做好左对齐。

## 集成测试里的几个用例

在仓库的 [integration.rs](https://github.com/pzweuj/ITDCall/blob/HEAD/tests/integration.rs) 里，我主要用模拟数据卡了几种典型场景：

1. **长片段探针捕获**：模拟 180 bp 重复 + 120 bp read，WT 和 Mut 生成等量片段（理论 AF 50%）。测试除了要求检出 `SVLEN=180`，还会把 VCF 的 `REF/ALT` 填回参考序列逐碱基核对，确保能还原出完整的突变序列，同时要求估算出的 AF 和 50% 相差不超过 12 个百分点。
2. **带额外插入的扩增子**：用前面 36 bp 重复加 3 bp 插入的组合，检查 `DUPLEN`、`INSLEN`、`SVLEN` 有没有拆对，再核对 60 对 WT 和 40 对 Mut 对应的 `AF` 与 `AR`。
3. **边界对照**：包括多克隆共存、单端测序（single-end）和纯 WT 阴性对照。

上面这些数字都来自模拟测试构造的基准，真放到实际临床 panel 上，不同文库和捕获效率下的检出限与定量偏差，后面还得拿真实样本再继续摸底。
